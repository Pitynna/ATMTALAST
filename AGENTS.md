# Правила проекта ATMTALAST

Рабочая папка и репозиторий — только этот каталог (`Z:\ATMTA\ATMTALAST`,
GitHub `Pitynna/ATMTALAST`). Не создавайте рядом копии проекта, «запасные»
каталоги и параллельные клоны.

## Сохранение работы (обязательно)

6 ноября 2026 вся несохранённая работа (астероид, ксеноархеология, Ulthor и
др.) была потеряна: в `tmp` лежали ссылки (junction) на `code`, `_maps`,
`icons` и другие папки проекта, и рекурсивное удаление `tmp` стёрло оригиналы.
Из-за этого:

1. **После каждой крупной задачи (и после каждого завершённого этапа внутри
   большой) делайте коммит и заливайте на GitHub (`git push`).** Не оставляйте
   сделанное только в рабочей папке. Если задача длинная — коммитьте и
   пушьте не реже чем раз в час работы.
2. Работайте в отдельной ветке (`codex/...` или `claude/...`), не в `master220`.
   Перед слиянием в `master220` ветка должна компилироваться без ошибок.
3. Перед коммитом проверяйте, что новые файлы не попали под `.gitignore`
   (`git status`, `git check-ignore -v <файл>`); исходники должны быть в коммите.
4. Скрипты и результаты проверок, которые нужны надолго, храните в `tools/`
   или `docs/`, а не только в `tmp/` (`tmp/` в `.gitignore` и не сохраняется).

## Запрещено

- Создавать junction/symlink на папки проекта (`code`, `_maps`, `icons`,
  `interface`, `html`, `sound`, `strings`, `tgui`, `SQL`). Для изолированных
  прогонов копируйте нужные файлы или запускайте сборку прямо в проекте.
- Удалять каталоги рекурсивно (`Remove-Item -Recurse`, `rd /s`, `rm -rf`,
  `shutil.rmtree`), не проверив, что внутри нет ссылок и что путь — не
  каталог проекта. Сначала `Get-ChildItem -Force -Recurse | Where Attributes -match ReparsePoint`
  (или аналог), затем удаление.
- `git clean`, `git reset --hard`, `git checkout -- .` и любые команды,
  затирающие незакоммиченные изменения, без коммита/копии перед этим.
